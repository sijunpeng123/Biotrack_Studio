# BioTrack Studio v1.0.0

[![Tests](https://github.com/sijunpeng123/Biotrack_Studio/actions/workflows/tests.yml/badge.svg)](https://github.com/sijunpeng123/Biotrack_Studio/actions/workflows/tests.yml)
[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)
[![Python 3.10](https://img.shields.io/badge/Python-3.10-3776AB.svg)](https://www.python.org/)

BioTrack Studio is a cross-platform napari workspace for cell segmentation,
tracking, consensus-assisted review, and manual correction. It is designed to
give wet-laboratory researchers one graphical workflow while keeping integrated
algorithms in isolated conda environments.

![BioTrack Studio consensus review](docs/images/03_tracking_consensus_review.png)

The interface screenshot uses the included 20-frame HeLa H2B-mCherry demo and
shows review sites produced by the released algorithms. The demo is not ground
truth and the displayed counts are not accuracy scores.

## Main Capabilities

| Workflow | Included options |
| --- | --- |
| Segmentation | Cellpose Cyto, Cellpose Nuclei, StarDist |
| Tracking | SC-Track, TrackPy, Ultrack |
| Manual correction | MMV_H4Tracks, napari-amdtrk |
| Tracking consensus | Primary tracker compared with a TrackPy reference from the same mask |
| Mask consensus | Primary mask compared with a reference mask generated by a different segmentation model |
| Review reporting | On-screen counts, manual classifications, event-level CSV, summary CSV |
| Algorithm management | Registry-based Algorithm Store with isolated environments |

BioTrack Studio standardizes data exchange between tools through a result folder
containing `image.tif`, `mask.tif`, `track.csv`, and `config.yaml`. The primary
results remain the correction target when consensus assistance is enabled.

## Supported Platforms

- Windows with conda or Miniforge
- macOS on Apple Silicon or Intel with conda or Miniforge
- Linux with conda, Miniforge, or a compatible conda installation

Napari requires a graphical display. Remote Linux users can use an X11 session,
including MobaXterm with X11 forwarding enabled.

## Quick Start

Download the complete release ZIP from GitHub Releases and extract it before
launching. Do not run launchers from inside the ZIP file.

### Windows

On a new computer, run:

```text
setup_conda.bat
winstart.bat
```

For later sessions, run `winstart.bat`.

### macOS or Linux

From the extracted folder, run:

```bash
bash setup_conda.sh
bash start.sh
```

For later sessions, run `bash start.sh`.

The first launch creates the application and algorithm environments. If setup is
interrupted, run the same launcher again; completed steps are reused.

## Input Format

The graphical Pipeline accepts an input folder containing one single-channel
2D time series. The folder may contain either one TIFF per time point or one
multi-page TIFF whose pages are time points. For separate frame files, use
zero-padded names such as `t000.tif`, `t001.tif`, and `t002.tif`. Do not mix the
two formats or place unrelated TIFF files in the folder. The Pipeline does not
select channels from multi-channel data.

## Cell Analysis Pipeline

Open **Plugins > BioTrack Studio > Cell Analysis Pipeline**.

![Cell Analysis Pipeline](docs/images/01_pipeline.png)

1. Choose the folder containing the single-channel 2D time series.
2. Choose a new, empty output folder.
3. Select segmentation and tracking options. The exact bundled UI values are
   `cellpose_cyto`, `cellpose_nuclei`, `stardist`, `sctrack`, `trackpy`, and
   `ultrack`.
4. Select **Run Analysis**.

Choose the segmentation method for the biological object being segmented.
Cellpose Cyto targets whole-cell or cytoplasm-like objects, whereas Cellpose
Nuclei and StarDist target fluorescent nuclei. These methods are not
interchangeable, and no bundled model is expected to suit every specimen.

Choose **Skip segmentation, use existing mask.tif** to track a compatible mask
already stored in the output folder. Choose **Skip tracking** to create only a
segmentation result in a folder without an older `track.csv`. At least one
Pipeline step must be selected. SC-Track requires at least 13 input frames.

## Optional Algorithm Store

Open **Plugins > BioTrack Studio > Algorithm Store** to refresh the online
catalog and install an additional method that has a BioTrack Studio adapter.
Each Store method uses an isolated conda environment. After installation, close
and reopen the Cell Analysis Pipeline to refresh its method lists.

The Store is not required for the bundled methods and does not install arbitrary
GitHub algorithms. A compatible segmentation adapter must write `mask.tif`; a
tracking adapter must write the standard `track.csv` and `config.yaml`. An empty
online list means that no additional validated adapter is currently published.
The remove action hides only Store-installed methods and keeps their environment
and downloaded files. Included methods cannot be removed or overwritten through
the Store. See the illustrated user guide for the complete procedure.

## Standard Result Format

A complete analysis produces:

```text
image.tif
mask.tif
track.csv
config.yaml
```

The standardized `track.csv` columns are:

```text
frame
trackId
state
continuous_label
Center_of_the_object_0
Center_of_the_object_1
```

The default cell state is `none` unless the selected tracking algorithm supplies
another state. `sctrack` and `ultrack` additionally write `lineageId` and
`parentTrackId`. A compatible Store adapter may write the same two optional
lineage columns; both must be present together and must use positive track and
lineage IDs, with `0` marking a track that has no parent.

## Manual and Consensus-Assisted Correction

Open **Plugins > BioTrack Studio > Manual Correction**.

![Manual Correction options](docs/images/02_manual_correction.png)

Standard correction opens the primary result in MMV_H4Tracks or napari-amdtrk.
napari-amdtrk **Save** updates the standard `mask.tif` and `track.csv` in place.
MMV_H4Tracks provides tab-based segmentation and tracking curation, but when
BioTrack Studio loads TIFF/CSV layers directly, its native save operation writes
a separate Zarr file and does not update the standard TIFF/CSV files. Use
napari-amdtrk when the corrected result must remain a BioTrack result folder.

Optional consensus assistance creates a dated correction copy and adds review
markers without replacing the primary track or mask. Tracking consensus compares
`sctrack` or `ultrack` with a TrackPy reference; TrackPy cannot be compared with
itself. Mask consensus performs a sampled compatibility check before running a
full reference segmentation with a different model for the same biological
target.

The Tracking tab separates different next-frame connections from segmented
objects missing in the primary tracking output. The Mask tab separates High
priority and Low-priority sites. Site-type and review-status filters keep these
categories visible without treating every disagreement as a confirmed error.

The Consensus Assistant lets a reviewer classify each marker as:

- **No issue:** primary result inspected and accepted;
- **Problem found:** real problem confirmed and still open;
- **Corrected:** required edit completed and saved; or
- **Reopen:** return a previous decision to the review queue.

It writes:

- `consensus_review_status.csv` for persistent review state;
- `consensus_review_report.csv` for one row per disagreement; and
- `consensus_review_summary.csv` for all, Tracking, and Mask statistics.

Review counts measure review progress. They are not an accuracy metric and do
not replace benchmarking against ground truth that was not used to train or
select the evaluated methods.

## Scientific Scope

Consensus assistance identifies algorithm disagreement, not truth. Two methods
can agree and still be wrong, and segmentation errors can affect all trackers
that use the same mask. Different models can also share training sources, so
their outputs are not statistically independent. Users must inspect the raw
image and biological context. Objective accuracy claims require ground-truth
data that were not used to train or select the evaluated models.

BioTrack Studio is research software and is not intended for clinical diagnosis.

## Reproducibility and Testing

The repository includes unit tests for:

- tracking and mask event loading;
- review status compatibility and classification;
- review statistics and CSV exports;
- mask matching, compatibility, priority thresholds, and split/merge events;
- Algorithm Store catalog validation, archive safety, included-method protection,
  removal choices, and Pipeline discovery; and
- the Consensus Assistant GUI when napari dependencies are available.

GitHub Actions runs non-GUI tests on Windows, macOS, and Linux with Python 3.10.
Run the complete local suite in an installed BioTrack Studio environment with:

```bash
python -m unittest discover -s tests -v
```
